# 增补验证清单

## 已做／未做

本机只进行 JavaScript 语法、手机增补 TSX 结构、UTF-8／JSON、接入点和代码路径静态核对。没有运行插件、模型、Relay、手机、安装、测试、编译或打包；`client.js`／`link.js` 仍需用户／CI 生成。没有创建 Release 或执行 npm publish；源码提交／推送按用户授权进行，以 Git 历史和远程 `main` 为准。

专用多代理／跨模型审查在当前工具环境不可用，采用人工式逐路径静态复核；不是独立审查通过证明。TypeScript 严格类型及 GUI 验收由用户／CI 完成。

## 实机验收

### 新建干净会话

1. 在固定 DSH 的测试数据副本准备一条带工具和思维链的旧私聊；保存一条可辨认的长期记忆，记录角色、模型、权限、工作目录及 Bot ID。
2. Bot 设置 → Manage → 新建会话：第一次点击只确认，第二次成功后当前 Session ID 变化，Bot ID 和以上设置／记忆不变；新会话发第一条消息时不携带旧思维链／工具消息／摘要，仍能使用长期记忆。
3. 翻阅／搜索旧历史，确认旧内容完整；群聊和后台任务的 Session ID 不变。分别检查主 Bot、普通 Bot、私有 Bot，以及本机 CLI 路由。
4. 当前私聊运行中、等待审批、存在排队消息或未答卡片时操作：显示可处理的拒绝原因，原会话继续保留。
5. 在两个窗口对同一旧 Session 发起操作：至多成功一次；创建期间发的新消息到新会话，刷新后无丢失／重复。切换模型或权限与新建并发时，不以旧设置提交。
6. 模拟创建、模型选择、权限设置或保存失败：保留原会话，不能出现成功导航；失败的新空白 Session 不加入 Bot 历史。
7. 创建一个未来的定时任务，再新建会话：任务转向新 Session，按时只投递一次；迁移失败时旧会话不归档，重启恢复后可完成迁移。
8. 第一击后换 Bot／切 Session 或按 Escape：需要重新确认；请求中离开设置页，旧回包不改变新页面。旧服务器不显示入口。

新建会话的新增回归已在 Actions `45571853126`（`23cdd80e`）的 Linux／Windows Node 24 测试通过；该轮工作流因手机 TSX 语法、登记序列／SSE 定位和桌面接口模拟未适配而失败，不是整体验收通过。本轮修复及新增接口回归仍需 CI／用户复验，本机没有运行测试。模型兼容错误是否消失仍需使用实际模型确认，新建会话不会修复模型服务自身的接口错误。

### queue／steer

1. 让 Bot 正在执行一个不会破坏数据的任务。
2. Bot 设为 `steer`，在桌面与手机分别发送补充内容：无需点队列 ↑，在安全边界读到新消息，不新建后台任务。
3. 设为 `queue`：当前回合不中途读取，完成后按次序处理。
4. 设为跟随基础设置，基础设插话：确认不再被强制 queue。
5. 修改模式前留一条旧排队消息：切换不会自动批量发送旧队列。Bot 间消息、审批答复及定时消息不受影响。

### 授权

1. 默认手机权限开关关闭、电脑授权关闭：Bot 详情／设置与群设置中的权限不能成功修改，普通改名／聊天正常；群“跟随每个 Bot 自身权限”按 `null` 清除群覆盖。
2. 电脑允许、手机不允许，仍拒绝；二者允许时每次设备解锁，取消不会发送；完全权限还需确认。
3. 浏览器设备即使叫 `DSBotDeck（Windows）` 或已获完整消息授权，也不能改权限、开 Agent 聊天或改电脑授权。
4. 按一个设备开启完整消息；另一个设备仍看不到内部协作／错误详情。
5. 撤销时正在读取工具下一页：旧回包丢弃，当前完整消息页被隔离。重新配对／改公钥不能继承。
6. 刻意用测试 Token（不是实际密钥）验证 JSON、命令、输出、错误、URL 认证脱敏；锁住密钥库时详情失败关闭。

### 工具／任务

1. 普通聊天、群成员、后台任务执行 read／bash／PTC 子调用：显示原名，未知状态不是成功。
2. 折叠工具摘要不加载参数／输出；展开参数／输出才请求，关闭后清空详情，长输出分页。
3. 工具失败和模型失败分别可见，重试／取消有状态；内部协作只在获授权设备展开。
4. 手机能读取正在运行与已结束的后台任务、翻历史，任务分段不混入继承的前台历史。
5. `todo_write` 成功后手机出现真实清单；失败调用、普通文字“全部完成”不能改变待办。群共享待办单独显示。

### 归档／内存

1. 准备最后活动分别在 23 小时、恰好 24 小时、24 小时以上的已结束测试任务。
2. 只处理超过 24 小时且没有新日志活动的旧会话；当前私聊、当前群段、运行／待审批／待输入／作业／定时投递不变。
3. 删除日志的动作不应发生；归档后仍可分页看历史。
4. 比较固定 DSH 的 Agent／Session 驻留数量、进程 private bytes／RSS；记录归档前、归档后 5 分钟、打开旧历史后的结果。
5. 若仅 archive 标记变化而驻留量／内存不变，记作“归档成功，底层未证实卸载”，不要以此宣称内存问题已修好。不得私改 DSH 私有 Map；需要上游公开卸载／驱逐接口后单独适配。
6. 极旧后台任务未保存继承历史边界，且没有已加载的 Agent 可核实时，增强读取会明确拒绝并提示电脑查看，不为补边界而加载归档 Agent，也不把继承的前台内容混进任务历史。

## 发布后观察与回滚触发

新建会话先由部署者在数据副本验证一次本机与网页操作、一次真实模型切换，以及一次定时任务触发。核对 Bot ID 不变、当前 Session ID 只变一次、长期记忆条目不变、新请求无旧思维链；检查原历史可读且新输入没有丢失或重复。搜索日志 `bot/busy`、`bot/stale`、`did not move on to a fresh part`、`input kept in part`、`moving schedules`；拒绝有未完成工作的会话是正常信号。出现当前会话或记忆丢失、重复投递、权限与 Bot 设置不一致、定时任务未迁移时，暂停使用新入口，保存日志和数据备份后回到原版。

由部署者在第一批数据副本上观察一个归档周期（至少 10 分钟）与一轮长任务；搜索日志“自动归档检查未完成”“旧会话”“bot/refused”。健康信号：无正在运行的会话被归档、授权拒绝符合预期、无额外重复投递、详情不自动成批读取。出现丢消息、误归档、错误授权、重复任务或持续内存上升时暂停增补部署，退出宿主，按 integration.md 用备份回到原版正式包。
