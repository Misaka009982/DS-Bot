## 实机验收

### 手机扫码的服务器名称

此功能属于当前未发布源码；已发布的 `addons-v0.3.10-1.0.0` 附件不包含这次修改，需用户／CI 重新生成客户端并打包。手机仍使用原配对协议，不需要修改手机源码。

1. 在服务器的设置 → 连接 → 手机中编辑“服务器名称”，例如“杭州服务器 + 100% & team”，保存后再显示二维码；手机扫码后的电脑列表使用这个名称，浏览器配对链接也携带同一名称。Relay 地址保持原值。
2. 名称留空保存后，下一张二维码使用系统机器名；名称上限与现有协议一致，为 64 个 UTF-16 代码单元，拒绝换行、控制字符和超限输入，不让扫码静默截断名称。
3. 在二维码已显示时修改名称：二维码和浏览器链接只更新 `name`，原一次性配对码、设备类别、地址、主机公钥和过期时间不变；旧二维码在原有效期内仍可配对，不因改名延长有效期。
4. 正常停止并重启测试宿主：名称保留，已配对手机无需重新授权；服务器改名不改系统主机名、访问令牌、开关或设备列表。手机已经保存的旧名称不会自动覆盖，要更新名称可重新扫码同一服务器，不必先忘记连接。
5. 模拟名称保存失败：显示错误并保留草稿、原名称和原二维码；手机和浏览器的 `phone-set` 仍由服务器拒绝。只读宿主不允许修改，编辑期间常规轮询不覆盖草稿。
6. 英文／中文界面、窄屏、IME Enter／Escape、快速重复保存及请求期间离开页面分别复核；旧服务器不显示名称编辑入口。不要输出或外传真实二维码、配对码、密钥或 `phone.json` 内容。

### 新建干净会话

1. 在固定 DSH 的测试数据副本准备一条带工具和思维链的旧私聊；保存一条可辨认的长期记忆，记录角色、模型、权限、工作目录及 Bot ID。
2. Bot 设置 → Manage → 新建会话：第一次点击只确认，第二次成功后当前 Session ID 变化，Bot ID 和以上设置／记忆不变；新会话发第一条消息时不携带旧思维链／工具消息／摘要，仍能使用长期记忆。
3. 翻阅／搜索旧历史，确认旧内容完整；群聊和后台任务的 Session ID 不变。分别检查主 Bot、普通 Bot、私有 Bot，以及本机 CLI 路由。
4. 当前私聊运行中、等待审批、存在排队消息或未答卡片时操作：显示可处理的拒绝原因，原会话继续保留。
5. 在两个窗口对同一旧 Session 发起操作：至多成功一次；创建期间发的新消息到新会话，刷新后无丢失／重复。切换模型或权限与新建并发时，不以旧设置提交。
6. 模拟创建、模型选择、权限设置或保存失败：保留原会话，不能出现成功导航；失败的新空白 Session 不加入 Bot 历史。
7. 创建一个未来的定时任务，再新建会话：任务转向新 Session，按时只投递一次；迁移失败时旧会话不归档，重启恢复后可完成迁移。
8. 第一击后换 Bot／切 Session 或按 Escape：需要重新确认；请求中离开设置页，旧回包不改变新页面。旧服务器不显示入口。

新建会话的新增回归已在 Actions `45571853126`（`23cdd80e`）的 Linux／Windows Node 24 测试通过；该轮工作流因手机 TSX 语法、登记序列／SSE 定位和桌面接口模拟未适配而失败，不是整体验收通过。随后 Actions `45583726517`（`4e01891b`）已通过手机严格类型、Linux Node 22／24 及三平台桌面单元测试；手机测试首次执行暴露了 7 个平台模块加载失败，本轮补齐对应夹具隔离和默认拒绝回归。此补丁和其余 CI／GUI 验收仍需复验，本机没有运行测试。模型兼容错误是否消失仍需使用实际模型确认，新建会话不会修复模型服务自身的接口错误。

### 主 Bot 暂停与会话恢复工具

此功能属于后续源码，不在已发布的 `addons-v0.3.10-1.0.0` 附件中。使用测试副本和无实际密钥的模型环境验收，不要对生产任务试验丢弃队列。

1. 普通 Bot 不显示两个工具；普通 Bot、无归属调用、自己、其他主 Bot、私有 Bot、群会话和后台任务不能被越权操控。新建期间撤销调用方主角色、将调用会话移入历史或开启目标私有保护，必须保留原会话并拒绝提交。
2. 主 Bot 对运行中的普通 Bot 调用 `pause_bot`：等待 `cancel` 和 `whenIdle` 真正确认当前模型轮次结束，不发起解释停止原因的新轮次，不改变群聊／后台任务；缺失宿主队列 API 时明确返回 `bot/unavailable`。
3. 队列中准备两条可辨认的输入：默认不暂停、不丢输入；只有显式 `discard_queued=true` 才取消，并返回实际 `discarded_count`。不能把 `paused=true` 当作任务完成，已丢请求不会自动重发。
4. 仅在 `new_session_ready=true` 时用返回的 `pause_id` 调用 `new_bot_session`：新当前私聊只创建一次，身份、记忆、模型、权限、工作目录和旧历史保留，不复制旧对话或调用模型写摘要。其他主 Bot／调用会话、目标新输入／新轮次、模型／权限／目录变化和超过 10 分钟均不能复用原回执。
5. 创建过程中收到新输入、取消请求或失去权限：保留原会话，失败的新空白会话归档，不能丢输入或伪装成功。并发请求只能切换一次。
6. 模拟定时迁移失败：返回 `handoff_pending=true`、`recovery_verified=false`，保留旧私聊恢复标记；再次暂停／新建必须拒绝，不继续创建会话。独立群聊或后台任务的切换标记不误拦前台私聊。
7. 切换后由主 Bot 按需重新提供完整任务；使用真实模型结果核对故障是否消除。不清仍存在的 `blocked`，不自动重放有副作用的旧操作，也不为网络、额度或密钥错误反复换会话。

### queue／steer

1. 让 Bot 正在执行一个不会破坏数据的任务。
2. Bot 设为 `steer`，在桌面与手机分别发送补充内容：无需点队列 ↑，在安全边界读到新消息，不新建后台任务。
3. 设为 `queue`：当前回合不中途读取，完成后按次序处理。
4. 设为跟随基础设置，基础设插话：确认不再被强制 queue。
5. 修改模式前留一条旧排队消息：切换不会自动批量发送旧队列。Bot 间消息、审批答复及定时消息不受影响。

### 授权

1. 默认手机权限开关关闭、电脑授权关闭：Bot 详情／设置与群设置中的权限不能成功修改，普通改名／聊天正常；群“跟随每个 Bot 自身权限”按 `null` 清除群覆盖。
2. 电脑允许、手机不允许，仍拒绝；二者允许时每次设备解锁，取消不会发送；完全权限还需确认。
3. 浏览器设备即使叫 `DSBotDeck（Windows）` 或已获完整消息授权，也不能改权限、开 Agent 聊天或改电脑授权。
4. 按一个设备开启完整消息；另一个设备仍看不到内部协作／错误详情。
5. 撤销时正在读取工具下一页：旧回包丢弃，当前完整消息页被隔离。重新配对／改公钥不能继承。
6. 刻意用测试 Token（不是实际密钥）验证 JSON、命令、输出、错误、URL 认证脱敏；锁住密钥库时详情失败关闭。

### 工具／任务

1. 普通聊天、群成员、后台任务执行 read／bash／PTC 子调用：显示原名，未知状态不是成功。
2. 折叠工具摘要不加载参数／输出；展开参数／输出才请求，关闭后清空详情，长输出分页。Web 和手机提示“已启用密钥保护”，不把每条工具标成已经遮盖；普通 `headers`／`env`／`environment`／JSON `data` 与命令／路径应可查看，只有敏感字段值和已知密钥遮盖。分别用无实际密钥的测试样例检查 `OPENAI_API_KEY`、`GITHUB_TOKEN`、`DSH_SECRET_*`、认证／Cookie 和名值数组；二进制不借工具详情传输。原 DSH／日志已遮盖的历史不能恢复。Web 下一页不插入换行、不删除已读开头，达到 128 Ki 字符上限明确提示不完整；`HTTP_401`／`HTTP_403` 后旧正文消失，关闭、切调用或撤销完整消息授权后的迟到回包不能恢复旧正文。
3. 工具失败和模型失败分别可见，重试／取消有状态；内部协作只在获授权设备展开。
4. 手机能读取正在运行与已结束的后台任务、翻历史，任务分段不混入继承的前台历史。
5. `todo_write` 成功后手机出现真实清单；失败调用、普通文字“全部完成”不能改变待办。群共享待办单独显示。

### 归档／内存

1. 准备最后活动分别在 23 小时、恰好 24 小时、24 小时以上的已结束测试任务。
2. 只处理超过 24 小时且没有新日志活动的旧会话；当前私聊、当前群段、运行／待审批／待输入／作业／定时投递不变。
3. 删除日志的动作不应发生；归档后仍可分页看历史。
4. 比较固定 DSH 的 Agent／Session 驻留数量、进程 private bytes／RSS；记录归档前、归档后 5 分钟、打开旧历史后的结果。
5. 若仅 archive 标记变化而驻留量／内存不变，记作“归档成功，底层未证实卸载”，不要以此宣称内存问题已修好。不得私改 DSH 私有 Map；需要上游公开卸载／驱逐接口后单独适配。
6. 极旧后台任务未保存继承历史边界，且没有已加载的 Agent 可核实时，增强读取会明确拒绝并提示电脑查看，不为补边界而加载归档 Agent，也不把继承的前台内容混进任务历史。

## 发布后观察与回滚触发

服务器扫码名称由部署者在新包首次启动、一次改名／扫码和一次正常重启内复核。健康信号：保存名称与扫码名称一致，旧设备继续在线且不要求重新授权，主机身份和 Relay 地址不变；`bot/invalid` 仅用于无效名称，保存失败明确可见且原名称／二维码保留。观察 `phone-set` 的 `bot/internal` 或持续保存失败；若改名导致原设备被移除、身份变化、配对码异常失效或明显名称串服，停用新入口、保存本机诊断与数据备份，再回到已验证的旧包。不要在日志、截图分享或反馈中输出真实配对码、私钥、访问令牌或 `phone.json` 内容。

新建会话先由部署者在数据副本验证一次本机与网页操作、一次真实模型切换，以及一次定时任务触发。核对 Bot ID 不变、当前 Session ID 只变一次、长期记忆条目不变、新请求无旧思维链；检查原历史可读且新输入没有丢失或重复。搜索日志 `bot/busy`、`bot/stale`、`did not move on to a fresh part`、`input kept in part`、`moving schedules`；拒绝有未完成工作的会话是正常信号。出现当前会话或记忆丢失、重复投递、权限与 Bot 设置不一致、定时任务未迁移时，暂停使用新入口，保存日志和数据备份后回到原版。

由部署者在第一批数据副本上观察一个归档周期（至少 10 分钟）与一轮长任务；搜索日志“自动归档检查未完成”“旧会话”“bot/refused”。健康信号：无正在运行的会话被归档、授权拒绝符合预期、无额外重复投递、详情不自动成批读取。出现丢消息、误归档、错误授权、重复任务或持续内存上升时暂停增补部署，退出宿主，按 integration.md 用备份回到原版正式包。
