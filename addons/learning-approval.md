# 每设备学习提案审批授权

增补 **1.3.0 / 0.4.0-addons.1**，固定上游 v0.4.0。入口在服务器 **连接 → 手机 → 已配对设备**，紧接“允许查看完整消息”的 **允许审批学习提案** 开关。

开关默认关闭，允许该设备批准或拒绝技能新增／更新和 AGENTS.md 修改提案。完整消息读取、远程权限修改和工作区／终端权限都不能代替此项。手机和浏览器配对均可由服务器本机单独授权；授权不把浏览器身份变成手机身份。

授权记录写在既有 `state.extras.deviceAccess[deviceId].learningApproval`，同一记录必须匹配实际 `identityKey` 和 `pairedAt`。名称改变不提权，设备删除、重新配对或换公钥不继承旧授权；客户端不能调用本机 `phone-extra-set` 给自己授权。授权保存期间拒绝远程写入，保存失败恢复原记录。

本机设置请求：

```json
{ "endpoint": "phone-extra-set", "payload": { "deviceId": "device-id", "pairedAt": 123, "learningApproval": true } }
```

远程 `state.extras` 与 `extra-status` 返回：

```json
{ "schema": 1, "learningApproval": { "schema": 1, "allowed": false } }
```

批准／拒绝仍使用 `learning-answer`，只接受原提案 `id` 与布尔 `approve`。服务端按真实配对身份在入口、异步准备及写入前复核授权，并保留服务器只读和提案版本／并发保护。Typert Gateway 没有此配对设备授权，不能借该开关审批。已经开始实际写入后的取消或撤销不能承诺撤销结果；客户端只查提案结算，不自动重发。

Deck 同步卡片按钮与主进程门禁；新服务器没有 allowed:true 时不可提交。缺少此能力声明的旧服务器保留旧手机权限行为，浏览器仍不可提交。升级服务端后既有设备默认需重新打开该开关。

回归定义包括独立权限、默认拒绝、设备归属、保存失败、浏览器专用例外、真实配对与真实 scheme 提交；本机未运行。实机验收需安装本轮新包，核对默认关闭、单设备授权、批准／拒绝结算、撤销、重新配对和断线结果查询；旧发布或旧 CI 不证明这些路径通过。
