# Bot 私聊目标模式

本功能从增补 1.2.0 提供，旧版 `addons-v0.3.10-1.1.0` 附件不包含。客户端生成、验证和打包由 CI 完成，实际结果以对应新 tag 的 Actions 和 Release 附件为准。只作用于 Bot 当前私聊，群目标与后台任务保留现有执行方式。

## 原因与入口

上游提交 `e7ffb9f8568f98ff9f492664d21079c58eb680e9` 为修复 [#133](https://github.com/Fei-Craft/DS-Bot/issues/133)，屏蔽 Bot 中的 DSH 会话级 Goal。群控制 Session 不调用模型，原生 Goal 曾造成空转；Bot 自动换段也不会自动迁移原生 Goal。当前私聊提示词要求长任务汇报后继续，但没有目标状态驱动已经结束的模型回合。

本增补保留原生 Goal 的拦截，在 Bot 记录上保存独立目标：

- 电脑／网页的 **Bot 设置 → 私聊目标模式** 填写目标与验收标准，点击“启动目标”。普通聊天不自动开启。只有有效消息发送方式为 `steer` 才可启动、恢复和续跑：Bot 单独指定 `steer`，或跟随基础且基础为 `steer`；显式 `queue` 优先于基础，DSH 默认不推定为 `steer`。
- 消息方式切离 `steer` 时，先暂停目标并移除尚未领取的目标续跑消息，再保存新方式；目标、进展和证据保留。基础方式变化只暂停受影响的跟随者，Bot 显式 `steer` 保持。切回 `steer` 不自动恢复；设置保存失败也不会复活已冻结的续跑。
- 支持命令装饰的 DSH 中，私聊输入裸 `/goal` 打开该 Bot 设置面板；带参数的原生命令仍走上游拦截。群里的 `/goal` 保持群目标入口。
- 面板显示目标、验收标准、进展、证据及暂停／阻塞原因，可调整、暂停、恢复或二次确认终止。
- 面板暂停／终止只停止后续自动推进；当前模型轮次仍可完成。需要立即结束当前工作时使用聊天停止按钮。宿主停止、手机停止、主 Bot 的 `stop_bot`／`pause_bot` 会同时暂停目标；手动新建会话也暂停，需确认后恢复。
- Deck 和原生手机设置面板没有在本改动中新增目标编辑入口；服务端端点可由已配对设备按原聊天授权调用。

## 状态与推进

`bot.extras.goal` 保存 `schema:1`、目标编号、`revision`、目标、验收标准、进展、证据、停止原因、自动续跑次数和连续无进展回合数。状态为 `active`、`paused`、`blocked`、`complete`、`stopped`；同一 Bot 同时只有一个未结束目标。新建不覆盖未结束目标。

自动推进只在有效消息方式为 `steer`、该 Bot 当前私聊空闲、没有队列／审批／问题卡片／输入表单／后台作业／子 Agent／私聊后台任务／待返回私聊协作、且不处于换段交接时入队。服务器每秒只核对这些状态；没有待续跑事项就不发送消息，不通过模型轮询或重复派活。

一次正常回合结束并不代表目标完成。仍为 `active` 时，服务器在上述条件满足后追加一条带目标编号的续跑消息；模型每轮读取当前目标，只推进剩余事项。正常自动换段后目标和进展跟随 Bot 保留，交接结束才向新段续跑。

模型通过 `bot_goal` 操作自己当前私聊的目标：

| action | 条件与效果 |
| --- | --- |
| `show` | 返回当前状态；不存在时返回 `null` |
| `progress` | 目标须为 active，提供当前 `goal_id`、`revision`、实际进展及证据；重复相同内容不算新进展 |
| `complete` | 提供进展与验收证据，并且没有未处理输入、问题、审批、后台或协作工作，才可结束自动推进 |
| `block` | 提供缺失输入／外部条件的具体原因，停止续跑；由用户恢复 |

模型不能创建、恢复、替换目标，不能从群聊、后台任务、旧段或其他 Bot 越权操作。证据是模型报告的可核对记录，服务器不自行执行验收命令，也不保证非空证据即真实完成。

连续三轮没有目标以外的工具行动、也没有新进展记录时，目标进入 `blocked`，避免只反复汇报或读取目标。无固定总轮数或总时长上限；实际推进仍会消耗模型额度。模型错误、宿主阻塞与用户取消不会被转换成成功；暂停／阻塞后普通消息照常处理，但目标不会自动恢复。

## 并发、持久化与重启

- `extra-goal-control` 是固定写端点，只接收 `botId`、`sessionId`、`action`、`goalId`、`revision`、`objective`、`acceptance`。普通设置端点不能混写 goal 或权限字段。
- 启动、修改、恢复带状态前置条件；旧会话、旧目标或过期 revision 拒绝。暂停／终止以目标编号为准，避免正常结算增加 revision 后用户无法及时叫停。
- 每次恢复更换执行标识。停止会立即冻结等待中的续跑请求，只移除该目标尚未领取的自动消息，保留用户队列。晚到的旧续跑在模型执行前再次核对；同批新的用户输入不被丢弃。
- 保存成功后才允许发送。保存或发送确认失败后冻结自动推进，保留可核查状态；不盲目重发。
- 宿主重启后保留目标但暂停，需要用户确认现场并恢复，避免重复执行已经产生副作用的操作。上游 `resume.js` 不再把目标自动回合变成普通恢复提示重放；普通用户请求和协作工作的恢复规则保持原样。
- `activation` 与执行标识只属于服务端状态，不出现在面板投影和模型工具返回中。目标不改变 Bot 权限、配对身份或运行账号。

## 验证

本机只做语法、UTF-8／JSON、接入锚点及 diff 静态核对；未执行运行测试、构建或安装。

回归定义在 `ds-bot/test/extra-private-goal.test.js`、`extra-private-goal-ui.test.js`，现有命令入口、安装顺序和前台保护测试同步覆盖接线。重点包括：`queue`／DSH 默认拒绝、继承与独立 `steer`、切换模式的迟到发送与落盘失败、切回后手动恢复，以及普通聊天不启动、部分汇报后续跑、完成证据及未完成工作门禁、用户停止与迟到发送、暂停后恢复的旧消息、正常换段、重启、只读和失效授权、保存失败以及无进展防空转。

用户／CI 验收时使用无个人数据的测试副本：启动目标，让模型输出阶段汇报并结束一轮，确认仍会继续；随后分别检查暂停、错误、审批、后台工作和换段，确认没有重复派活。实际模型是否如实记录进展与完成证据，需要实机验收。
