# DS-Bot 正式版增补

本分支以 DS-Bot **0.3.10** 的固定提交 `d104d9ca18d69a35460f14e15dff4d553181433a` 为基线。增补版本 `1.0.0`，npm 安装包版本 `0.3.10-addons.1`。不跟随 `dev` 或滚动 `main`，不修改 DSH。

## 功能入口

| 位置 | 增补 |
| --- | --- |
| 电脑／手机 → Bot 设置 → 增补设置 | 每 Bot 选择跟随基础设置、`queue` 或 `steer`；显式插话自动送入当前工作，不再手点队列 `↑` |
| 电脑／网页 → Bot 设置 → Manage（管理）→ 新建会话 | 确认后创建干净 Session，保留长期记忆和 Bot 设置，旧聊天仍可查看 |
| 同一增补设置 | 自动归档开关。未单独选择时，显式 `queue` Bot 默认开启；其他模式默认关闭 |
| 电脑 → 连接 → 手机 | 允许远程修改 Bot／群权限，默认关闭 |
| 电脑 → 已配对设备下方 | 对该设备授权／撤销“查看完整消息”，包括内部 Bot 协作、脱敏模型错误和重试详情 |
| 手机 → 设置 → 手机 | 当前配对电脑的远程权限防误触开关，默认关闭；每次权限修改都需要原生解锁，完全权限另行确认 |
| 手机 → Bot 详情／设置、群设置 → 权限 | 选择真实 DSH 权限预设；群可恢复跟随各 Bot，自身未获授权或在浏览器中时只读，解锁取消／写入失败不假装已保存 |
| 聊天 → 工具摘要 | 默认折叠名称列表，展开后看到工具原名、说明和成功／失败／未确认；参数、输出按需读取 |
| 手机聊天上方 → 执行待办／后台任务 | 工具待办、群共享待办、后台任务及分页过程；已结束任务不会因不再运行而消失 |
| 电脑配对设备列表 | 优先显示保存的客户端名称。Deck 可显示 `DSBotDeck（Windows）`，名称不影响权限类别 |

`steer` 在模型／工具的安全边界读取新输入，不会强行中断外部工具，也不自动批量搬动切换模式之前的旧队列。基础发送设置仅影响真实用户输入，Bot 之间投递、定时任务和审批答复保持原逻辑。

## 新建会话

用于切换模型后旧思维链／历史消息格式不兼容等情况。在 Bot 设置的 **Manage（管理）→ 新建会话** 再点一次确认；成功后打开新的当前私聊。主 Bot、普通 Bot 和私有 Bot 都可使用。

Bot 身份、长期记忆、角色指令、模型、权限、工作目录及增补设置保留。新 Session 不 fork 旧会话，不复制旧消息、思维链或交接摘要，也不请求模型生成摘要。旧会话保存在原历史链中，仍可阅读和检索；尚未写入长期记忆的临时上下文不会自动带入。群聊与后台任务继续使用各自的会话。

当前私聊正在运行、排队、等待审批／答复或协作时拒绝操作，先完成或停止相关工作。创建期间到达的新输入通过原交接流程保留并转交；定时任务在归档前迁移，迁移失败保留原会话和恢复标记。创建／权限应用／提交失败时保留原会话；过期请求不会重复创建。该功能仅是此次用户指定的增补例外，上游关于连续对话与已撤回并行会话的设计文档不改写，旧的 `bot-new-part`／`bot-open-part` 端点仍关闭。

新界面按服务器的 `extras.newSession` 能力显示，调用 `extra-new-session` 并携带 `botId` 与用户确认时的 `sessionId`。此操作不修改权限预设，不允许附带其他设置字段。手机原生界面此次未增加入口。

## 授权边界

- “查看完整消息”与“修改远程权限”完全独立。仅想看模型失败，不需要打开权限修改开关。
- 完整消息授权由电脑保存，绑定 **设备 ID、公钥及配对时间**。名称改变不提权，删除／重新配对不能自动继承旧授权。
- 浏览器权限设备也可获得完整消息的**读取**授权，但仍不能调用原本禁止的敏感 RPC，也不能进入 DSH Agent 聊天。电脑授权不能由手机、网页或 Typert Gateway 修改。
- 所有已配对设备能看到基本失败、重试、取消状态；未经授权不返回详细错误正文和内部协作文本。
- 工具详情与完整消息仅显示脱敏文本，不执行其中的 HTML／代码；认证字段、已知密钥、常见 Token 和 URL 认证信息被遮蔽。密钥库锁定时拒绝完整消息及工具详情。认证类错误仍隐藏原始正文／堆栈，避免服务商回显局部凭据；授权设备可以看到错误码和状态。
- 脱敏是防意外回显，**不是对任意未知敏感正文的绝对保证**。授权设备应视为可读取团队业务内容的可信终端；不能替用户判断普通文件内容中的所有隐私。
- 撤销后拒绝新请求；手机隔离授权等级缓存并清空当前页面／工具详情。已被合法设备保存、截图或复制的内容不能追回。

## 自动归档与内存

启动 30 秒后检查，随后每 5 分钟检查；每批最多 32 个候选，轮转处理，避免繁忙候选挡住后面的旧会话。

仅选择最后活动超过 **24 小时**的已结束后台会话及旧段。当前私聊、当前群成员段、活跃后台任务、未知任务状态，以及带排队消息、审批、未答卡片、切段／交接、作业、子代理或定时投递的会话均跳过。读取日志后再检查一次活动状态。

归档走公开的 `workspaceRegistry.archiveSession`，不用 `stopActivity`，不删日志／任务，不取消工作。历史分页优先读取持久化记录，不为显示旧段自动创建 Agent。本机 CLI 的旧会话在归档后通过既有关闭接口释放。

**不承诺归档标记本身就释放全部 DSH 内存。** 是否卸载底层 Agent／Session、GC 何时回收和 RSS 是否下降，需要在固定 DSH 实机验收；增补不通过删除内部 Map、强制 GC 或修改 DSH 安装目录来伪造效果。见 [验收清单](verification.md)。

## 安装包只放 GitHub Releases

无需 npm 账号、npm Token 或 `npm publish`。`release-addons.yml` 使用已有依赖与 `npm pack` 生成：

- `ds-bot-0.3.10-addons.1.tgz`
- `SHA256SUMS-addons.txt`
- `BUILD-INFO-addons.json`：记录上游提交、增补版本、源码提交和 SHA256。

发布 tag 必须是 `addons-v0.3.10-1.0.0`，并与 `manifest.json` 一致。原版基线和增补版是两个独立验证 job；两者成功后才上传 Releases。上游 `release.yml` 在派生仓库跳过，避免触发 npm Trusted Publishing。手动运行增补 workflow 只生成 Actions Artifact，不自动创建 Release。

`.tgz` 是 **DSH 插件包**，不是 Windows 安装程序、手机 APK 或完全离线依赖包。手机界面源码位于 `mobile/src/extras/`，需要重新构建手机应用／网页版才能看到新入口；本流程不替换安卓签名或冒充上游 APK。安装 `.tgz` 时 DSH／npm 仍可能从公开 npm registry 取得它已有的依赖，这与注册 npm 发布账号无关。

下载后先核对 SHA256，再用 DSH 现有的本地包安装方式导入该 `.tgz`。包名仍是 `ds-bot`，是原版的替换版本，**不要把原版和增补版同时启用**。先备份数据，再在副本上验证。不要用 `npm install -g ds-bot` 代替本地文件，以免安装到 npm 上的上游版本。

## 用户／CI 执行的命令

本机代理只做静态检查，未执行以下安装、测试、构建或打包命令。请在不指向个人 DSH 数据的环境由用户执行。普通 `main` CI 的 Node 24／22 插件测试在 `addons/manifest.json` 存在时先运行 `npm run build`，再保留原测试及生成文件一致性检查；没有增补清单的原版流程不变。

仓库根目录：

```powershell
node addons/check.mjs
```

依赖准备、生成及插件验证（在各自目录执行，不手工编辑 `client.js`／`link.js`）：

```powershell
# link/
npm ci
npm test
# ds-bot/
npm ci
npm run harness
npm run build
npm test
npm run lint
# mobile/
npm ci
npm run typecheck
npm test
```

完成验证后回到仓库根目录：

```powershell
node addons/pack.mjs
```

`pack.mjs` 只在系统临时目录改包版本，不修改源码的 `package.json` 或 lockfile，不上传 npm。临时目录会打印并保留供用户检查；用户确认后自行清理。当前工作区的生成文件尚未更新时，不能把旧的 `client.js`／`link.js` 直接当增补版发布。

## 同步上游

接入点见 [manifest.json](manifest.json)，维护方法见 [接入清单](integration.md)。后续只选新的正式 Release；先验证完全不含增补的原版，再逐个核对接入点。不能把本清单当作适用于任意上游版本的自动补丁。

增补开发分支为 `feat/stable-addons`；源码提交／推送按用户授权进行，以 Git 历史和远程 `main` 为准，不会自动打 tag 或发布。本轮没有改动 `DSBotDeck/`，其已有工作区变更保持原样；Deck 对只读上游源码有自身固定锚点，若要单独构建 Deck，应仍给它提供原版正式提交的参考源码，不能直接把此增补分支当作已兼容的 Deck 构建基线。
